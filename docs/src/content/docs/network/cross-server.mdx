---
title: Cross-server chat
description: Sharing channels, private messages, mentions and mutes between servers over Redis, NATS or RabbitMQ.
---

import { Steps, Tabs, TabItem, Aside } from '@astrojs/starlight/components';

Voxen talks to its other instances directly through a message broker. There is nothing to
install on the proxy, and BungeeCord or Velocity are not required at all: two standalone
servers pointed at the same Redis work just as well.

## Setting it up

<Steps>

1. Pick a transport in `integrations.yml` and fill in its connection details:

   <Tabs syncKey="transport">
   	<TabItem label="Redis">
   		```yaml title="plugins/Voxen/integrations.yml"
   		network:
   		  transport: redis
   		  server-id: lobby
   		  redis:
   		    host: 10.0.0.5
   		    port: 6379
   		    username: ""
   		    password: "secret"
   		    ssl: false
   		    channel: "voxen:chat"
   		```
   	</TabItem>
   	<TabItem label="NATS">
   		```yaml title="plugins/Voxen/integrations.yml"
   		network:
   		  transport: nats
   		  server-id: lobby
   		  nats:
   		    url: "nats://10.0.0.5:4222"
   		    username: ""
   		    password: ""
   		    subject: "voxen.chat"
   		```
   	</TabItem>
   	<TabItem label="RabbitMQ">
   		```yaml title="plugins/Voxen/integrations.yml"
   		network:
   		  transport: rabbitmq
   		  server-id: lobby
   		  rabbitmq:
   		    host: 10.0.0.5
   		    port: 5672
   		    username: guest
   		    password: guest
   		    virtual-host: "/"
   		    exchange: "voxen.chat"
   		```
   	</TabItem>
   </Tabs>

2. Give every server a **unique** `server-id`. It is how servers tell each other apart and
   what gets written into the chat log.

3. Mark the channels that should be shared:

   ```yaml title="plugins/Voxen/channels/global.yml"
   cross-server: true
   ```

   The bundled `server` channel already has it, so you have a local-only channel from the
   start.

   Some channels cannot be shared, because the other servers have no way to check who
   belongs to them: anything with a `radius`, type `world`, type `party` and any channel
   with a `scope`. If you set `cross-server: true` on one of those, Voxen turns it back off
   and says so in the console.

4. Set a shared `network.secret`, the same random string on every server:

   ```yaml title="plugins/Voxen/integrations.yml"
   network:
     secret: "a-long-random-string"
   ```

   Every outgoing message is signed with it (HMAC-SHA256) and anything arriving with a
   wrong or missing signature is dropped.

   If you run behind Velocity you can skip this. With `secret` left empty Voxen picks up
   the forwarding secret from `config/paper-global.yml`, which every backend server behind
   the proxy already shares, and derives its own key from it. Set
   `use-velocity-secret: false` if you would rather it did not.

   Servers also have to agree on the time, because a message older than
   `network.max-age-seconds` (60 by default) is thrown away. If your machines run NTP,
   which they should, there is nothing to do here.

5. Restart every server. Repeat the same `integrations.yml` everywhere except
   `server-id`.

</Steps>

`transport: none` is the default and keeps Voxen in single-server mode.
`reconnect-seconds` and `timeout-millis` control connection recovery and how long a lookup
of a player on another server may take.

## What crosses the network

| Feature | Behavior |
| --- | --- |
| Channel messages | delivered to every server, rendered with `external-format` when set |
| Mentions | `@name` finds the player wherever they are and respects their toggle |
| Private messages | `/msg` and `/r` reach any server |
| Social spy | every PM is broadcast so each server can show its own spies |
| Mutes | applied everywhere the moment they are set |

## Where things are decided

Formatting permissions are applied **on the sending server**. The message is rendered
there and travels as finished MiniMessage text, so what a player may write depends on
their permissions where they typed it. Servers can run different Paper builds.

The receiving side decides what belongs to it: the mention toggle, the PM toggle, chat
visibility and the ignore list are all checked on the recipient's server. Chat carries the
sender's UUID for that reason, so ignoring someone works no matter which server they are on.
A sender with `voxen.bypass.ignore` still gets through, the same as locally.

## Private messages

Tab completion only suggests local players, but any name can be typed. If nobody on the
network has that player, the sender gets the not-found message after `timeout-millis`.

The `/r` target lives in player data. With a shared MySQL database it follows players
between servers and survives relogs; with per-server SQLite each server keeps its own.

Every outgoing message gets its own id and the answer carries it back, so two messages sent
one after another cannot mix up their answers. An answer is only accepted once, and only if
the sender and the typed name match what was sent; anything else is ignored. The timeout
covers a single message rather than the whole conversation.

A server-wide mute also blocks `/msg` and `/r`. Set `respect-mutes: false` in
`modules/private-messages.yml` if a mute should only cover public chat.

## Mutes

`network.sync-mutes` is on by default and broadcasts every `/voxen mute` and `unmute`
immediately. With shared MySQL mutes also survive restarts on every server. With
per-server SQLite each server only knows about mutes it was online to receive.

## Signing

Without `network.secret` Voxen trusts whatever the broker hands it, so anyone who can
publish to Redis, NATS or RabbitMQ can fake a chat message from any player, send private
messages as somebody else, or mute anyone. Set the secret and that stops: messages are
signed on the way out and verified on the way in.

The signature covers the whole message plus the time it was sent, so nobody can edit a
captured message or backdate it. On top of that Voxen drops anything that is:

| Dropped | Why |
| --- | --- |
| older than `max-age-seconds`, or dated that far into the future | somebody is replaying an old message, or two clocks disagree |
| bigger than 256 KiB | someone is trying to make the server chew on junk |
| stamped with another protocol version | one of the servers runs a different Voxen build |
| already seen | the same message arrived twice |

The key itself is never sent anywhere, so a derived Velocity secret cannot leak back out
of the broker. Servers behind *different* proxies end up with different keys and will
ignore each other, so set `secret` by hand in that case.

The same string has to be on every server. A mismatch means the servers silently ignore
each other, so Voxen logs one warning per reason the first time it drops a message, and
one on startup if the secret is empty while a transport is on.

<Aside type="caution" title="Keep the broker private">
	Signing proves who wrote a message, it does not hide it. Chat and private message
	contents travel in the clear unless you configure TLS on the broker itself. The broker
	should not be reachable from outside your network, and it should need a password.
</Aside>

<Aside type="note">
	Slowmode and `/voxen mutechat` are per server and are not broadcast. Run them on each
	server, or mute the channel everywhere with a scripted command.
</Aside>
